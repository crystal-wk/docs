## RFC: Skill Review quality gate

This PR adds a production path for Skill quality governance: deterministic review facts, a read-only review tool, a public reviewer skill, and a diff-scoped CI gate for changed public skills.

### Why this matters

<br>Before this change, Skill quality checks were mostly split between manual review and safety scanning. That left several gaps:

- A Skill could be structurally valid enough to load, but still have unclear triggers, broken resources, weak evidence, or unsafe review boundaries.
- Reading a target Skill for review could be confused with loading that Skill for execution unless the two paths were explicitly separated.
- CI had no reusable, machine-readable facts layer for public Skill quality gates.
- Reviewer feedback was hard to standardize across authors, maintainers, and future automation.

### What this PR changes

- Adds a read-only review core under `backend/packages/harness/deerflow/skills/review/`.
- Adds versioned JSON contracts under `contracts/skill_review/` for review facts and reports.
- Adds the built-in `review_skill_package` tool, which returns `review_subject_entry` metadata instead of `skill_context_entry`, so reviewing a Skill does not activate it.
- Adds `skills/public/skill-reviewer/` as the human-friendly semantic review entry point.
- Adds `scripts/review_changed_public_skills.py` plus `.github/workflows/skill-review-ci.yml` so PRs only review changed `skills/public/**/SKILL.md` owning packages.
- Uses `--fail-on error`, so deterministic `error` and `blocker` findings fail CI while warning-level calibration findings remain advisory.

### Key boundaries

- Review is read-only.
- Review does not install the target Skill.
- Review does not execute target scripts.
- Review does not bind target `required-secrets`.
- Review does not apply the target Skill's `allowed-tools` to the reviewer.
- Model-based semantic review remains advisory; deterministic facts are the CI gate.

### Benefits

- **PR-level quality gate**: public Skill changes now get an automated deterministic check before merge.
- **Smaller CI blast radius**: the workflow is diff-scoped, so it reviews only changed public Skill packages instead of scanning every Skill on every PR.
- **Safer architecture**: review and execution are separated, which avoids context, secret, and tool-policy contamination.
- **Reusable facts layer**: `review-facts.v1` can be consumed by CI, future UI reports, installation preflight, and `skill-creator` workflows.
- **Lower reviewer burden**: maintainers get consistent blocker/error/warning output instead of re-deriving basic package quality issues manually.
- **Clear upgrade path**: deterministic gates can stay strict while semantic readiness scoring evolves independently.

### Verification

<br>Local verification covered:

- focused Skill Review tests: `19 passed`;
- bundled Skill and SkillScan fixture-boundary tests: `44 passed`;
- `make lint` for backend formatting and ruff checks;
- no-op diff runner smoke;
- real `skill-reviewer` package review with `--fail-on error`.

<br>The CI failure found after opening this PR was useful: it proved the new gate was active. The follow-up fixes now exclude reviewer calibration fixtures from being treated as real public Skill packages while keeping the actual root Skill review enforced. |

**Size limits trust the declared `info.file_size`, not actual decompressed bytes.**

`max_file_bytes`/`max_total_bytes` gate on `info.file_size` from the zip's central directory (lines 279, 284), but `zf.read(info)` (line 293) decompresses the real stream. A crafted archive can declare a small `file_size` while its deflate stream decompresses far more, bypassing both limits and exhausting gateway memory. Since this tool is a builtin reachable on any allowlisted `.skill` under `/tmp`/cwd/skills-root, a user-supplied malicious archive reviewed via the tool is a plausible DoS path.

Classic high-ratio bombs (honest huge `file_size`) are already caught; this is the spoofed-declared-size gap. Consider streaming `zf.open(info)` in chunks and aborting + marking `truncated` once actual decompressed bytes exceed the limit, rather than trusting `info.file_size`.
