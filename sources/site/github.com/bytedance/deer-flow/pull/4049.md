## Summary

Adds runtime metadata (effective model + cumulative token usage) to sub-agent task cards.

Two commits:

1. **`feat(subagents): show runtime metadata on task cards`** — collapsed sub-agent cards show the effective model and, when the provider returns usage metadata, a cumulative token total that updates after each completed sub-agent LLM call and persists after reload. `task_started` carries the effective `model_name`; `task_running` carries a cumulative usage snapshot; terminal `ToolMessage` metadata (`subagent_model_name` / `subagent_token_usage`) restores the values after reload. Absent provider usage stays absent (never estimated as zero); the token total respects the `token_usage` config switch. The cross-language status contract is extended additively so older consumers are unaffected.

2. **`fix(subagents): stop task-card render loop and dedupe model fetches`** — code-review fixes (below).

## Review fixes in commit 2

**P1 — infinite render loop.** The terminal `ToolMessage` is re-parsed on every `MessageList` render and always carries `modelName`/`usage`, so the presence-based `setTasks` condition fired a fresh state object each render → `Maximum update depth exceeded`. Fix:

- `computeNextSubtask` returns a `changed` flag that **value-compares** `usage` (a re-parse rebuilds it into a new object each render, so reference comparison would always look changed).
- A new pure `subtaskNotification(task, {becameTerminal, changed})` → `"eager" | "deferred" | "none"` routes terminal transitions through the deferred after-render path and drops no-op re-parses, replacing the loop-prone inline condition.

**P2 — per-card `useModels` refetch.** Each subtask card mounted its own `useModels()` observer with default `staleTime: 0`, so newly-mounted cards refetched `/api/models`. Added `staleTime: Infinity` (model config is session-stable) so all cards share one fetch.

## Known limitation (follow-up)

Runtime metadata is **not** restored after a **user-stop + reload**: the `except asyncio.CancelledError` path produces no terminal `ToolMessage`, and the reload backfill reads only `subagent.step` events, so a backend-only change would write data nothing reads on reload. A complete fix needs coordinated backend + frontend work and is deferred (noted in [#4048](https://github.com/bytedance/deer-flow/issues/4048)).

## Testing

- New unit tests in `subtask-update.test.ts` pin the render-loop regression (`changed` value-comparison + all three `subtaskNotification` routing cases, including the terminal re-parse → `"none"` case).
- `pnpm test tests/unit/core/tasks`, `pnpm typecheck`, `pnpm lint`, and the backend subagent suites pass.

> The render-loop fix is anchored at the state-management layer (a pure, testable function) since a full React-render regression test would require adding `@testing-library/react`, which is not currently a dependency.
