Fixes [#4728](https://github.com/bytedance/deer-flow/issues/4728)

## Why

When a user uploads files, the generated conversation title may include the server-injected `<current_uploads>` context instead of reflecting the user's actual request. This makes the conversation title noisy and less useful for finding the thread later.

## What changed

- Title generation now prefers the server-preserved original user content when upload or other context wrappers have been injected.
- Attachment-only messages intentionally retain the existing `New Conversation` fallback instead of deriving a title from the server-generated upload wrapper.
- Added regression coverage for LangChain message objects, checkpoint-deserialized message dictionaries, attachment-only messages, and ordinary structured content.
- Documented the title-generation behavior in the backend documentation.

## How

- `UploadsMiddleware` continues to enrich the message content for downstream agent execution, while preserving the unwrapped user text in `additional_kwargs["original_user_content"]`.
- `TitleMiddleware` reuses `get_original_user_content_text()` when a valid original user string is present.
- Messages without valid original-user metadata retain `TitleMiddleware`'s existing structured-content normalization and fallback behavior.
- Only the input used for title generation changes; the original conversation messages and upload context are left unchanged.

## Compatibility

This is a targeted backend behavior fix. Messages without `original_user_content` keep the existing title-generation path, ordinary structured content keeps its previous normalization behavior, and no frontend or API contract changes are required.
