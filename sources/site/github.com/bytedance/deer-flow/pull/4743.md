## Summary

- add an admin-only multipart endpoint for uploading and installing one offline `.skill` package
- reuse the existing archive validation, security scanning, user-scoped installation, and prompt-cache refresh flow
- add an `.skill` file picker to the Skills settings page with loading, success, and backend error feedback
- refresh the Skills query and switch to the Custom tab after a successful installation
- document the existing thread-path install API and the new direct-upload API
- harden direct uploads so authorization and a streaming request limit run before multipart materialization
- configure the Docker, local, and Helm nginx routes for archive-sized streaming uploads

## Scope

This PR intentionally supports direct offline `.skill` uploads only. Git URL and arbitrary local-path installation are out of scope.

Closes [#4718](https://github.com/bytedance/deer-flow/issues/4718)

## Security and cleanup

- requires an authenticated administrator before multipart parsing begins
- rejects filenames without the `.skill` suffix
- caps uploaded archives at 512 MiB and complete multipart requests at 513 MiB
- rejects oversized `Content-Length` values before parsing and counts streamed/chunked request bytes cumulatively
- closes partial multipart spools and removes installation staging directories on failure
- uses an exact nginx upload route with matching limits and request buffering disabled in Docker, local, and Helm configs
- runs the same archive traversal, ZIP bomb, executable, static, and configured security scans as the existing install path
- preserves structured security-scan error messages in the UI
