Fixes [#4389](https://github.com/bytedance/deer-flow/issues/4389)

## Why

Generic and MCP tool calls currently fall through to a label-only renderer. The 
frontend already has the call arguments and the paired `ToolMessage` result, but 
Debug mode only adds token metadata, so users must inspect logs or persisted 
events to verify values passed between tools.

This change follows the scope discussed on the issue: the payload view is 
frontend-only, restricted to Token Usage → Debug, and collapsed by default.

## What changed

- Generic tool steps in Debug mode now expose a collapsed **Tool details** 
 section with the tool name, call ID, formatted input, and result or error.
- Input and output each have a copy action. Copied content is the same bounded 
 representation shown in the UI.
- Tool failures retain `ToolMessage.status` / 
 `additional_kwargs.deerflow_tool_meta.status`, allowing the output to be 
 labelled as an error instead of a successful result.
- Payload formatting is deferred until expansion and bounded per field to 4,000 
 characters, 100 collection entries, and 12 nesting levels. Truncated content 
 has an explicit marker.
- Existing specialized renderers (`bash`, browser tools, file tools, search, 
 etc.) are unchanged.

There is deliberately no client-side secret-redaction heuristic in this PR. 
The payload is already present in the browser, and the frontend has no existing 
redaction policy to reuse. Enforcing redaction before data reaches the client is 
separate backend work.
