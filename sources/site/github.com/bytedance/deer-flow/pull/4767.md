## Why

- Copying the Lark authorization link used `navigator.clipboard.writeText` directly.
- In browsers or contexts where the Clipboard API is unavailable at click time, the copy action fails even though DeerFlow already has a shared clipboard fallback helper.

## How

- Route the Lark auth link copy action through `writeTextToClipboard`.
- Keep the existing success/error toast behavior based on the helper result.
- Add E2E coverage that removes `navigator.clipboard` and verifies the fallback copies the pending authorization URL.

## Validation

- `cd frontend && ./node_modules/.bin/eslint src/components/workspace/settings/integrations-settings-page.tsx tests/e2e/integrations.spec.ts`
- `cd frontend && ./node_modules/.bin/playwright test tests/e2e/integrations.spec.ts -g "falls back when copying a Lark authorization link without the Clipboard API"`
