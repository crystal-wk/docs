## Summary

Fixes [#4714](https://github.com/bytedance/deer-flow/issues/4714). `TodoMiddleware.wrap_model_call` / `awrap_model_call` overrode the parent `TodoListMiddleware` methods but never called `super()`, silently dropping the base-class system-prompt injection that tells the model about the `write_todos` tool. As a result, the custom todo system prompts passed in by `create_deerflow_agent` (`_TODO_SYSTEM_PROMPT`) and `_create_todo_list_middleware` (lead agent) never reached the model — they were dead code.

The `write_todos` tool itself stayed bound (registered in the parent `__init__`), so strong models could still trigger todos from the tool description alone, but the intended prompt-layer guidance was gone.

## Root cause

The `wrap_model_call` override was introduced in [#2907](https://github.com/bytedance/deer-flow/pull/2907) to inject transient completion reminders. It replaced the parent implementation entirely:

```python
return handler(self._augment_request(request))
```

Every other DeerFlow middleware overrides `wrap_model_call` without calling `super()` because their parent (`AgentMiddleware`) is a pure pass-through — but `TodoListMiddleware` is not: its `wrap_model_call` appends the `write_todos` system prompt to the request's system message. This override dropped that behavior.

## Fix

Chain through the base class, applying the reminder augmentation on the request that already carries the injected system prompt:

```python
def wrap_model_call(self, request, handler):
    return super().wrap_model_call(request, lambda req: handler(self._augment_request(req)))

async def awrap_model_call(self, request, handler):
    async def augmented_handler(req):
        return await handler(self._augment_request(req))
    return await super().awrap_model_call(request, augmented_handler)
```

`ModelRequest.override()` uses `dataclasses.replace` and preserves `runtime`, so the reminder drain in `_augment_request` keeps working.

## Tests

- Rewrote the `MagicMock`\-request based wrap/awrap tests to use real `ModelRequest` instances (they would break once `super()` accesses `request.system_message`).
- Added regression assertions: the request delivered to the handler must carry a system message containing `write_todos`.
- Extended the real-agent-graph integration test to assert the model's first call receives a `SystemMessage` containing `write_todos` (previously the model saw no todo guidance at all).
