## Summary

- Add backend-neutral `MemoryReadError` and `MemoryAccessError` outcomes to the `MemoryManager` contract.
- Make fail-open backends return empty context, while strict backends raise the shared read error and prompt assembly propagates it without inspecting backend-private policy strings.
- Preserve strict policy across the async middleware's caller-owned injection timeout, including when manager/config resolution itself fails.
- Keep proven credential, permission, and owner-identity failures fatal for reads and writes while preserving ordinary availability policies for transient and upstream-provider failures.
- Make OpenViking startup warmup verify public service health and authenticated USER-key filesystem access before reporting the backend healthy.

## Before / after

OpenViking's configured strict read policy had not propagated through prompt assembly since the official backend was introduced.

Before this change, OpenViking correctly selected `failure_policy.read: raise`, but the official retriever could surface raw SDK or network exceptions. Prompt assembly only propagated `MemoryManagerError` when it found Mem0's private `fail_closed` string, so a real OpenViking connection failure was logged and silently degraded to empty context.

After this change, each backend owns policy translation at the `MemoryManager` boundary:

- OpenViking `fail_open` returns empty context; `raise` produces `MemoryReadError`.
- Mem0 `fail_open` returns empty context; `fail_closed` produces `MemoryReadError`.
- Generic prompt and middleware code consumes only shared exception types/capabilities. DeerMem and third-party backends retain their existing fail-open compatibility default.
- The middleware timeout path resolves strictness through the shared contract. Missing credentials, invalid backend policy, or an unknown manager class conservatively make the timed-out read fatal without replacing the original `TimeoutError`; cancellation remains unaffected.
- Explicit OpenViking owner mismatch remains a fatal `MemoryAccessError`.

## OpenViking access provenance

OpenViking can map both caller USER-key denial and upstream embedding/VLM provider HTTP 401/403 failures to the same SDK `UnauthenticatedError` or `PermissionDeniedError`. The SDK exception class alone therefore cannot prove which credential failed.

OpenViking warmup now keeps the public `/health` check and performs one bounded, read-only official-client filesystem request:

```
ls("viking://user/memories", node_limit=1)
```

This authenticated, non-semantic probe does not invoke embedding/VLM providers, create a session, write, commit, capture, or download full memory content. Startup reports healthy only after both checks succeed. `startup_policy: fail_fast` raises `MemoryAccessError` for a denied USER key and `MemoryManagerError` for other failed/unverifiable checks; `warn` logs the cause and reports the backend unhealthy.

When a semantic read or write returns an ambiguous SDK authentication/permission exception, DeerFlow runs that same filesystem probe once:

- If the probe is also denied, caller access is proven invalid and the operation raises `MemoryAccessError` regardless of availability policy.
- If the probe succeeds, the caller key is valid; the original semantic failure follows `read: fail_open|raise` or `write: log_and_drop|raise` and is not mislabeled as USER-key denial.
- If the probe fails for a non-access reason, DeerFlow does not invent a caller denial; the original operation still follows its configured availability policy, with the verification failure logged.

The probe is not added to successful read/write hot paths. Partial-write wrappers retain explicit cause-chain classification.

## Why real transport tests matter

The dead-port regression binds an isolated loopback TCP port without listening and points the official OpenViking adapter at it with a 100 ms timeout. This exercises the real SDK/retriever transport path, including raw `httpx.ConnectError` and the async `aget_context` worker-thread path. A fake manager that raises `MemoryManagerError` would not reproduce the original read-policy bug.

The access-provenance regressions use an isolated local HTTP server and the official SDK paths for `/health`, `/api/v1/fs/ls`, and `/api/v1/search/find`. Real OpenViking `UNAUTHENTICATED`, `PERMISSION_DENIED`, and `UNAVAILABLE` envelopes distinguish caller-key denial from semantic provider failure while proving that the authenticated probe is bounded and read-only.

## Scope

This PR is intentionally limited to memory failure-policy translation, prompt/timeout propagation, typed access-failure classification, OpenViking startup/access provenance validation, documentation, and regression coverage. It does not add query-aware or turn-based recall and does not change capture design, compaction, idle timers, shutdown behavior, Gateway APIs, UI, setup flows, or broader lifecycle behavior.
