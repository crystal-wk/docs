## Why

The uploads middleware and the `list_uploaded_files` tool maintain duplicate extension-count summary logic. Keeping both implementations in sync adds unnecessary maintenance risk and previously led to a follow-up refactoring issue.

## What changed

- Added a public shared formatter for stable, neutralized extension-count summaries.
- Kept caller-specific extension extraction in the uploads middleware and historical uploads tool.
- Moved the shared untrusted-tag neutralization primitive into the lightweight `deerflow.utils.input_sanitization` module so upload helpers do not depend on agent middleware.
- Added focused unit coverage for counting, ordering, iterable inputs, empty iterables, and untrusted-tag neutralization.
- Documented ownership of the shared helpers in the backend architecture guide.

## Pull request overview

This PR refactors backend upload-related extension-count summaries by extracting shared formatting and sanitization helpers into lightweight, reusable modules, reducing duplication between the uploads middleware and the `list_uploaded_files` tool while preserving behavior.

**Changes:**

- Introduces a shared `format_extension_counts()` helper for stable extension-count summaries, reused by both the uploads middleware and `list_uploaded_files`.
- Moves the tag/boundary neutralization primitive into `deerflow.utils.input_sanitization` and updates the input sanitization middleware (and tests) to use it.
- Adds focused unit tests covering counting, ordering, iterable inputs, empty iterables, and untrusted-tag neutralization.
