## Why

DeerFlow's persisted run event stream did not have a canonical specification connecting event producers, storage backends, consumers, payload schemas, and compatibility rules.

This made producer/consumer drift difficult to detect and blocked reliable audit and evaluation integrations.

## What changed

- Added a canonical runtime event catalog for event names and categories.
- Added a machine-readable JSON contract for envelopes and payload schemas.
- Documented current producers, consumers, storage semantics, compatibility rules, and known gaps.
- Documented backend-dependent serialization behavior for `run.end`.
- Added compatibility documentation for the legacy `ai_message` event.
- Added conformance tests covering Memory, JSONL, and database persistence.
- Added validation for middleware event-name length and malformed subagent lifecycle events.

**This import inverts the persistence -> runtime layering and bloats import cost.**

`runtime/events/catalog.py` is a leaf in source (imports only `dataclasses`), but importing it triggers `runtime/__init__.py`, which eagerly loads `checkpointer`, `runs`, `store`, `stream_bridge`, and `serialization` (plus `runtime/events/__init__.py` loads `store.base`/`store.memory`). So a SQLAlchemy model in the foundational persistence layer now drags in the entire runtime stack just to read the integer `32`.

Verified this doesn't crash today (the catalog body is self-contained, and the runtime `__init__` chain doesn't import `persistence.models.run_event` at module level), but it's an architectural inversion: anything importing this model standalone - a migration, a CLI tool, a stripped-down env - now pulls in LangGraph/stream-bridge deps it doesn't need, and could break if `runtime/__init__` later grows a dependency unavailable there.

Since the only thing needed here is the column-width constant, consider defining `RUN_EVENT_TYPE_MAX_LENGTH` in a true leaf module (e.g. `persistence.base` or a small `persistence.constants`) and having the catalog import _from_ there (runtime -> persistence, downward). Keeps the single-source-of-truth goal without the upward edge.
