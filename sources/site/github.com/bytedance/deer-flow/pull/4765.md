## Why

The public showcase route currently imports the workspace route module directly, which couples one App Router entry point to another. The showcase mock-mode check also repeats the route prefix as a string literal.

This follow-up addresses the two review suggestions left on [#4635](https://github.com/bytedance/deer-flow/pull/4635) without changing chat behavior.

## What changed

- Moved the chat page implementation into a shared workspace chat component.
- Kept both the workspace and public showcase routes as thin entry points that render the shared component.
- Added a shared `SHOWCASE_ROUTE_PREFIX` constant and reused it for route generation and mock-mode detection.
