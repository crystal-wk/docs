Stream tool output in real-time like Claude Code — currently users only see tool results when the entire call completes.

## Changes

### Backend

- **ToolStreamingMiddleware**: wraps async tool calls to emit `tool_output_chunk` custom stream events (start, error, final completion signal); tools can emit intermediate partial chunks themselves via `langgraph.config.get_stream_writer()`
- **ToolStreamingConfig**: single `enabled` flag (default false)
- **worker.py**: always includes `custom` stream mode so `get_stream_writer()` works (also used by LLM retry hints, SafetyFinishReasonMiddleware, and the task tool)
- Positioned **inner** of ToolErrorHandlingMiddleware so raw tool exceptions reach the streaming error-chunk path first; `GraphBubbleUp` control-flow signals are re-raised untouched; the ordering is pinned by a regression test

### Frontend

- **ToolStreamingProvider** + `useToolStreaming` / `useToolCallStream` hooks: streaming state keyed by `tool_call_id`; partial chunks accumulate; a final or error chunk tears the entry down (the canonical ToolMessage carries the full result), so the map only ever holds actively-streaming calls
- **SubtaskCard**: renders live tool output scoped to the card's own active tool calls
- **hooks.ts**: maps `tool_output_chunk` custom stream events via `toolStreamUpdateFromEvent`
- **backend/AGENTS.md**: middleware-chain section documents the new middleware

## Design

- **Disabled by default** — fully backward compatible
- **Graceful degradation** — if the stream writer is unavailable the middleware passes through silently; a frontend without streaming events simply never populates the store
- **Error resilience** — a tool exception emits an error chunk before re-raising for ToolErrorHandlingMiddleware (outer) to convert to an error ToolMessage
- **No double payload** — the final chunk carries only a short first-line preview (max 200 chars) as a completion signal; the full result arrives via the canonical ToolMessage

## Tests

- Backend 29 (test\_tool\_streaming\_middleware.py): chunk builders, content extraction, enable/disable toggle, stream-writer fallback, start/final/error chunk emission, writer exception handling, dict-format regression, and a graph-level regression driving the middleware through a real compiled LangGraph `astream(stream_mode="custom")` channel (no writer mock); plus test\_tool\_streaming\_is\_inner\_of\_tool\_error\_handling in test\_tool\_error\_handling\_middleware.py pinning the middleware ordering
- Frontend 11 (tool-streaming.test.ts): exercises the exported production reducer and event mapper directly — guard direction (final accepted, late partial dropped), partial accumulation, per-tool-call scoping (P1-2), teardown on final/error, provider rendering
