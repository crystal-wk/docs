## Why

[Buzz](https://github.com/block/buzz) is Block's open-source, Nostr-based team workspace built around agents being first-class members with their own cryptographic identity. DeerFlow already bridges Feishu, Slack, Telegram, Discord, DingTalk, WeChat, WeCom and GitHub; Buzz is the same shape of integration, and it lets a self-hosted DeerFlow answer @mentions and DMs in a self-hosted workspace. Design and open questions are in [#4648](https://github.com/bytedance/deer-flow/issues/4648).

## What changed

A new `channels.buzz` block connects DeerFlow to a Buzz relay as a workspace member. It discovers the channels it belongs to, picks up new ones live (no restart), answers @mentions in channels and plain messages in DMs, and streams answers by posting one message and editing it in place. Off by default; enabling it needs the new optional `buzz` extra (`uv sync --extra buzz`).

New files:

- `backend/app/channels/buzz_nostr.py` — pure NIP-01 helpers: canonical event ids, BIP-340 signing/verification, chat/edit/auth builders, relay frames. No I/O, no wall-clock (callers pass `created_at`), so it is fully unit-testable.
- `backend/app/channels/buzz.py` — `BuzzChannel`.
- `backend/app/channels/buzz_run_policy.py` — same-thread serialization, mirroring `feishu_run_policy`.

Registration follows the existing pattern: `service.py` registry + credential keys, `manager.py` capabilities + policy import, `channel_connections` provider metadata, `config.example.yaml` (both `channels:` and `channel_connections:` blocks), docs.

## Notes for reviewers

Two relay behaviours were established empirically against a live buzz-relay and drove the design — they are not visible from the code alone:

1. **One subscription per channel is required.** A global `{"kinds":[9]}` REQ receives nothing; a multi-value `"#h"` filter also receives nothing. Only single-channel `"#h"` subscriptions get fan-out. This matches Buzz's own `buzz-acp` harness (`subscribe_channel_from(channel_id, …)`). Channel discovery is a historical `{"kinds":[39000]}` query over the same socket; membership changes arrive live on `{"kinds":[44100,44101], "#p":[self]}`.
2. **Watermarks are per channel.** A single global `since` cursor drags past a quiet channel's unread messages once a busy channel advances it (~28h of skew measured on one identity). Per-channel cursors only ever cost replay, which the manager's `event_id` dedupe absorbs.

Security posture: inbound events are signature-verified (event id recomputed, BIP-340 checked) before anything authorizes on `pubkey`, because the relay operator is not necessarily the DeerFlow operator. The remaining documented trust assumption is kind-39000 channel-metadata authorship, which can relax the mention requirement and induce a chat subscription but cannot bypass the pubkey allowlist.

Known limitations, documented in the connector docstring and `IM_CHANNEL_CONNECTIONS.md`: the relay caps historical delivery at 2000 events newest-first, so >2000 unread in one channel across a disconnect loses the oldest; Blossom media attachments are not implemented (`send_file` returns False).

## Surface area

- [x] **Backend API** — new IM channel under `backend/app/channels`
- [x] **Dependencies** — new optional extra `buzz` → `coincurve` (BIP-340 signing for Nostr events), lazily imported; `detect_uv_extras` resolves it from `channels.buzz.enabled` like the existing `channels.discord` rule
- [x] **Docs / tests** — `backend/docs/IM_CHANNEL_CONNECTIONS.md`, `backend/AGENTS.md`, `README.md`; 195 new tests

No default behavior change: the channel is disabled unless configured, and nothing else reads the new extra.

## Testing

- 195 new tests (`test_buzz_nostr.py`, `test_buzz_channel.py`, plus a `detect_uv_extras` case): protocol vectors, the full inbound gating matrix, streaming/edit/oversize/degrade paths, reconnect + NIP-42 bootstrap, per-channel subscription and discovery, live membership add/remove.
- Full backend suite on this branch rebased onto `main`: **10951 passed, 68 skipped, 0 failed**. `make lint` and `ruff format --check` clean.
- Verified end-to-end against a live self-hosted buzz-relay: channel @mentions, DMs without a mention, streaming in-place edits, a channel created and joined while running, and the same code running in a Docker deployment via `make up`.
