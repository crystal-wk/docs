## Why

DeerFlow currently treats MCP calls as ordinary in-run tool calls. When the remote work takes minutes or longer, the Agent turn must remain occupied, or the remote task ID has to be carried through model-visible conversation and polled manually.

This PR establishes the durable runtime boundary for long-running MCP work. The database, rather than model context or `ThreadState`, owns the remote task handle and recovery state, so later ordinary `submit/status/cancel` tools and a future MCP Tasks/SEP driver can share the same lifecycle.

This is the first implementation step only. Existing MCP tools remain synchronous until a concrete driver and user-facing integration are added.

## What changed

- Added a protocol-neutral `McpTaskDriver` contract with normalized `submitted`, `working`, `input_required`, `completed`, `failed`, and `cancelled` states.
- Added the durable `mcp_tasks` SQL record for remote handles, poll scheduling, a consecutive poll-error counter (failed polls increment it, applied snapshots reset it; the upcoming driver-layer backoff policy consumes it), lease ownership, pending notifications, results, errors, and future cancellation state.
- Added a Gateway-owned background poller. Workers claim due tasks under expiring leases, and a status result is accepted only from the worker that still owns the lease.
- Isolated unexpected failures between claimed tasks, and made Gateway shutdown cancel in-flight polling so a hung external status call cannot block process exit.
- Expired claims are recoverable after restart; `input_required` and terminal states stop polling and become pending for later Agent/UI delivery.
- Added startup-only `mcp_tasks` configuration, disabled by default. Durable recovery requires SQLite or PostgreSQL; the in-memory backend does not initialize this repository.
- Updated the example configuration, Helm-embedded configuration version, documentation, migrations, and regression tests.

Not in this PR: a concrete ordinary-tool or SEP driver, public list/cancel endpoints, Agent wake-up, delivery of `input_required`, or frontend task UI.

**backend/app/mcp\_tasks/service.py:88**

- `run_once()` uses `asyncio.gather()` without exception isolation. If any `_poll_one()` raises (e.g., a transient DB error while applying one snapshot), `gather()` will cancel the remaining polls and the method will exit early, leaving other claimed tasks leased until expiry. Wrapping each poll in a per-task try/except keeps the poller making progress even when one task fails.

```
            limit=self._max_concurrent_polls,
```
