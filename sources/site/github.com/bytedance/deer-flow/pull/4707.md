## Summary

This extracts the first, self-contained part of [#4637](https://github.com/bytedance/deer-flow/pull/4637): replacing DeerFlow's hand-written OpenViking HTTP client with the maintained `langchain-openviking` package.

- Removes the backend-local HTTP client and response models.
- Uses `OpenVikingSessionRecorder` and `OpenVikingRetriever` from `langchain-openviking==0.1.0`, backed by `openviking-sdk`.
- Supports one DeerFlow user with one credential-bound OpenViking USER API key. DeerFlow configuration no longer accepts trusted account/user fields or a root key for normal memory traffic.
- Keeps the current DeerFlow integration points unchanged: fixed-query recall, completed-turn capture, pre-compaction capture, and one commit per accepted capture.
- Keeps one stable OpenViking Session per DeerFlow thread and maps the default or named agent to a collision-safe actor peer.
- Preserves confirmed batch progress and pending commit retries in a bounded, hash-only local cursor.

The official package now owns SDK transport, message conversion, tool-call/result preservation, 100-message batching, retry behavior, and client lifecycle. DeerFlow continues to own when recall and capture run.

## Scope

This PR deliberately does not change the shared `MemoryManager` contract, lead-agent prompt assembly, memory middleware, summarization hook, Gateway startup, or lifecycle scheduling. Query-aware refresh and additional lifecycle behavior will be proposed separately after maintainers agree on the generic DeerFlow extension points.

DeerMem remains the default backend. OpenViking remains opt-in with `memory.manager_class: openviking` and `memory.mode: middleware`.

## Configuration change

The initial supported path is single-user/personal deployment:

```yaml
memory:
  manager_class: openviking
  mode: middleware
  backend_config:
    base_url: http://127.0.0.1:1933
    owner_user_id: default
    api_key_env: OPENVIKING_API_KEY
```

`OPENVIKING_API_KEY` must contain an ordinary USER API key, and the OpenViking server must use `api_key` mode. Existing trusted-mode fields (`auth_mode` and `account`) are rejected with migration guidance. Data previously captured under the old synthetic trusted-user mapping is not silently reassigned to the new credential-bound namespace.

DeerFlow explicitly supplies the URL and API key, uses request-local actor selection for memory operations, and passes an empty `extra_headers` mapping so arbitrary HTTP headers are not inherited from `ovcli.conf`. Before enabling this backend, remove legacy `OPENVIKING_ACCOUNT` and `OPENVIKING_USER` values from DeerFlow's `.env` and service environment, and remove `account` and `user` defaults from `~/.openviking/ovcli.conf`.

Recall continues to use overview content by default, matching the previous backend. Richer full-content retrieval remains available as an explicit `retrieval.content_mode` choice rather than becoming an implicit behavior and latency change in this refactor.
