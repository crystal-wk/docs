## Why

`GET /messages/page` re-introduced [#4152](https://github.com/bytedance/deer-flow/issues/4152): `_enrich_thread_message_page` inlined its own `turn_duration` loop that stamped **every** AI message of a run, so a multi-step turn rendered the same run lifetime beside every intermediate AI message and read as repeated thinking latency. The legacy `GET /messages` and `GET /history` endpoints already route through `stamp_turn_duration_on_last_ai` after [#4163](https://github.com/bytedance/deer-flow/pull/4163), but that fix missed the page endpoint introduced earlier in [#4065](https://github.com/bytedance/deer-flow/pull/4065).

## What changed

- The page endpoint now stamps `turn_duration` on the run's **last** visible AI message only, matching the legacy and history endpoints. All three message endpoints now agree.

## Surface area

- [ ] **Frontend UI**
- [x] **Backend API** — `GET /api/threads/{id}/messages/page` per-run `turn_duration` field
- [ ] **Agents / LangGraph**

- [ ] **Skills**
- [ ] **Dependencies**
- [ ] **Default behavior change** — only the page endpoint changes; intermediate AI messages of a multi-step run no longer carry a duplicate `turn_duration`
- [ ] **Docs / tests / CI only**
