## Why

Triaging incoming PRs and issues is fully manual today: no area/size/risk 
signals, no first-time-contributor flag, no triage queue. This adds automatic, 
namespaced labels so maintainers can scan and prioritize at a glance. This is 
the auto-labeling half of a small intake-quality change (the issue-template half 
is submitted separately; the two are independent — either can merge first).

## What changed

- **`.github/labels.yml`** — declarative source of truth for 29 namespaced 
 labels (`area:*` / `size/*` / `risk:*` / priority / status).
- **`scripts/sync_labels.py` + `label-sync.yml`** — idempotent label sync. Runs 
 on push to `main` whenever `labels.yml` changes and creates/updates the labels 
 via `GITHUB_TOKEN`. See "No manual setup" below.
- **`labeler.yml` + `pr-labeler.yml`** — `area:*` labels from changed paths 
 (`actions/labeler`), aligned with the pull request template's Surface area.
- **`pr-triage.yml`** — `size/*` (by churn), `risk:*` (by touched paths), 
 `needs-validation` (when a PR touches the front/back contract surface: 
 gateway API, agents, or the frontend streaming client), `first-time-contributor` 
 (by `author_association`), and `reviewing` (when a maintainer reviews).
- **`issue-triage.yml`** — `needs-triage` on every new issue (self-healing if 
 the label is missing).

## Security note (please read)

All PR workflows use `pull_request_target` **but never check out or execute PR 
code** — they only read the changed-file list and PR fields via the API. This is 
the documented-safe pattern for labeling fork PRs without exposing secrets.

## No manual setup on merge

`label-sync.yml` creates all 29 labels on its first run (the push to `main` that 
merges this PR), so maintainers do **not** need to pre-create any labels for the 
labelers to work.

## Surface area

- [x] **Docs / tests / CI only** — no runtime behavior change
