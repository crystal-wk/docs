Fixes [#4603](https://github.com/bytedance/deer-flow/issues/4603)

## Why

DeerMem currently decides whether information may be useful later, but does not distinguish task/project/user scope, transient versus durable information, or descriptive facts versus current-task authority. As a result, a one-off instruction such as “this PR must not modify the API” can be promoted into the `user_id × agent_name` long-term memory bucket and influence unrelated future tasks.

This also creates an authority risk: historical memory must never turn “inspect only”, “you may push”, or similar task-local instructions into permission for a new task.

## What changed

- Memory candidates are now classified in the existing extraction response by `scope`, `durability`, and `authority`; only `user + durable + descriptive` facts pass a deterministic fail-closed gate.
- Global summaries, fact removals, and consolidation use equivalent scope checks. Remove-plus-replacement updates stay atomic when a replacement is rejected or trimmed.
- Classification fields remain extraction-only, so the change adds neither an LLM call nor a persisted schema migration.
- Scope-gate metrics now break rejection counts down by facts, summaries, removals, consolidations, and reason, with a warning for unusually high rejection rates.
- Prompts, documentation, fixtures, and regression coverage now distinguish one-off task constraints and permissions from durable user preferences.
- **Upgrade note**: deployments overriding the bundled extraction prompts via `memory.backend_config.prompts_dir` must add the new classification fields to their custom `memory_update` / `consolidation` templates. The gate fails closed, so an un-migrated template stops extraction-driven fact/summary/removal writes; the `rejected_by_scope_gate` breakdown and the high-rejection-rate warning are the operator signals.

## Pull request overview

This PR hardens DeerMem’s long-term memory pipeline so task-/project-scoped constraints and one-off action permissions cannot be promoted into durable user memory, addressing the authority/isolation risk described in [#4603](https://github.com/bytedance/deer-flow/issues/4603).

**Changes:**

- Add extraction-time `scope`/`durability`/`authority` classification and enforce a deterministic, fail-closed write gate (facts, summaries, removals, consolidations).
- Make contradiction removals scope-aware and atomic with replacement survival (post gate + dedup + trim).
- Expand regression coverage and update documentation/prompts to distinguish durable user facts from thread/project constraints and transactional permissions.
