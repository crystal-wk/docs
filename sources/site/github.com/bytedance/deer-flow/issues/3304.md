## Context

This is a follow-up tracking issue from [#3301](https://github.com/bytedance/deer-flow/pull/3301).

In [#3301](https://github.com/bytedance/deer-flow/pull/3301) we only cleaned low-risk docs, smoke-test helpers, examples, and comments that still pointed users toward the old standalone LangGraph Server startup path.

The current standard runtime is Gateway-embedded:

- `make dev`, Docker dev, and production run the agent runtime inside Gateway.
- Nginx exposes `/api/langgraph/*` for LangGraph SDK compatibility and rewrites it to Gateway native `/api/*` routes.
- There is no standalone `langgraph` service in the default service topology.

Maintainer guidance: track the deeper cleanup separately and work on it after `2.0.0-m1` is released.

## Proposed cleanup scope after 2.0.0-m1

Before making code changes, first confirm whether direct standalone LangGraph Server / Studio compatibility is still a supported developer path.

If maintainers confirm it is no longer needed, we can clean up direct-server-only compatibility pieces such as:

- `backend/app/gateway/langgraph_auth.py`
- `backend/tests/test_langgraph_auth.py`
- `auth.path` in `backend/langgraph.json`
- docs that describe direct standalone LangGraph Server as an active path
- dependencies that are only needed for the removed direct-server path, if proven unused, for example:
 - `langgraph-api`
 - `langgraph-cli`
 - `langgraph-runtime-inmem`

## Non-goals

- Do not remove core LangGraph usage. DeerFlow still uses LangGraph for the agent workflow.
- Do not remove `langgraph-sdk` or Gateway `/api/langgraph/*` compatibility, because the frontend and channel integrations still rely on the LangGraph-compatible API surface.
- Do not remove LangGraph Studio/tooling support unless maintainers explicitly confirm it is no longer supported.
- Do not change standard Gateway request routing or auth behavior as part of the cleanup unless required by the removed direct-server path.

## Acceptance criteria

- The standard Gateway-embedded runtime remains unchanged.
- `/api/langgraph/*` continues to work through Gateway for frontend and SDK clients.
- Direct standalone LangGraph Server-only files/config are removed or clearly documented as still supported.
- Related tests are updated or removed with replacement coverage where needed.
- Dependencies are only removed after confirming they are no longer used by runtime, tests, tooling, or Studio support.
- CI passes.
