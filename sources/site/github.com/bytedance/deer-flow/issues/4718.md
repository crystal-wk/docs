### Problem / motivation

目前系统的技能创建流程强依赖于内置的 skill-creator SKILL。虽然该工具能够完成技能的生成与系统安装，但在实际使用中存在以下局限： 
1、生成质量瓶颈：自动创建的技能可能无法完全满足用户的个性化需求，用户常感觉生成的技能存在缺陷或逻辑不完善 
2、缺乏灵活性：用户无法直接使用社区、第三方或自己精心调试好的成熟技能包 
3、协作与复用困难：优秀的技能无法以文件形式在用户间流转，导致重复造轮子

### Proposed solution

1、支持用户上传/指定本地路径安装离线技能包 
2、安装后的技能可被系统正确识别、加载并用于对话 
3、提供基础的安装反馈（成功/失败原因）

注：最好是用户提供一个git地址，系统自己拉取SKILL并安装都对应目录下（非必要）

### Affected area(s)

Skills

### Alternatives considered

可以正常安装已有SKILL并使用

这个需求目前需要拆成几部分看：

- 本地 `.skill` 包的安装链路已经存在：将 `.skill` 上传到对话后，管理员可以从产物区点击 **Install**；后端会安装到当前用户的自定义 Skill 目录并刷新缓存。相关基础能力见 [RFC: Extract Shared Skill Installer and Upload Manager into Harness #1216](https://github.com/bytedance/deer-flow/issues/1216) / [refactor: extract shared skill installer and upload manager to harness #1202](https://github.com/bytedance/deer-flow/pull/1202)、[【BUG】上传本地skills文件，因为权限问题，智能体无法读取相关文件 #3235](https://github.com/bytedance/deer-flow/issues/3235) / [Fix custom skill install permissions #3241](https://github.com/bytedance/deer-flow/pull/3241)、[\[Feature\] User创建了自己的skill时应该像agent能保存在该user目录下的skills 并支持用户目录skills挂载到sandbox #2905](https://github.com/bytedance/deer-flow/issues/2905) / [feat(skills): per-user custom skill isolation with sandbox mounting #3889](https://github.com/bytedance/deer-flow/pull/3889)。
- 从 Git 仓库地址安装与 [\[feat\] 目前企业场景下使用的痛点和功能建议 #4357](https://github.com/bytedance/deer-flow/issues/4357) 第 6 条重叠，社区已有 [feat(skills): add community skill registry with install command #1824](https://github.com/bytedance/deer-flow/pull/1824) 这一实现方向，但目前尚未合并。
- 当前 Skills 设置页确实只有“创建 Skill”，没有直接的“上传离线包 / 输入 Git 地址”入口。

麻烦确认你希望补充的是：

1. 在 Skills 管理页增加 `.skill` 上传和安装入口；
2. 允许非管理员用户安装自己的 Skill；
3. 支持从 Git 仓库地址安装；
4. 还是以上都需要？

确认后可以进一步收敛范围，避免重复实现现有安装链路。

感谢说明。我理解目前已有两条安装/发布路径：

1. 用户可以在 Agent 对话中提供 Skill 的 GitHub 地址，将其安装到 User Space；
2. Public Skill 通过 skill-creator 的评审发布流程管理，开发者也可以直接向仓库根目录的 `/skills/public` 写入文件。

想进一步确认一下：是否仍接受一个小范围 PR，在 Skills 设置页增加本地 `.skill` 文件的上传和安装入口？

该 PR 只复用现有安装、安全扫描、用户目录隔离和缓存刷新链路，不重复实现 Git 地址安装，也不改变 Public Skill 发布流程或现有权限模型。

如果对话安装是项目有意保留的唯一入口，我就不再增加重复的设置页入口。
