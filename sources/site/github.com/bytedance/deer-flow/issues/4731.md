### Problem / motivation

RFC [#1898](https://github.com/bytedance/deer-flow/issues/1898) concludes DeerFlow should not bind to a single memory framework and instead keep a unified memory contract with pluggable providers. It explicitly lists **Honcho** as the user-dimension candidate — "suitable for user profiling and long-term preference modeling" — but no Honcho provider exists behind the `MemoryManager` contract today. Deployments that want durable cross-session user modeling (especially self-hosted, local-first setups where Honcho's server-side deriver does the extraction work instead of DeerFlow spending its own LLM calls) currently have no option in `backends/`.

### Proposed solution

Add a `backends/honcho/` memory backend behind the existing `MemoryManager` seam, as a drop-in with no core changes — the same shape the OpenViking backend took ([#4509](https://github.com/bytedance/deer-flow/pull/4509) → [#4707](https://github.com/bytedance/deer-flow/pull/4707)):

- Passive `add()` ingestion (cheap message writes; Honcho's server-side deriver owns extraction/consolidation — **no local LLM calls**); `get_context` returns the user's working representation; `search` supports tool mode; `requires_passive_writes_in_tool_mode = True`.
- **Multi-user isolation by construction**: one Honcho workspace per `user_id` with a collision-resistant default derivation, `workspace_overrides`/`user_peer_overrides` for deployments that deliberately share or rename workspaces, and fail-closed behavior when no user resolves.
- No new dependencies (httpx is already a core harness dep); mem0's `allow_insecure_http` posture for plain-HTTP + api\_key.

**Implementation is up as PR [#4730](https://github.com/bytedance/deer-flow/pull/4730)** — validated against the full offline suite (11106 passed), the blocking-io gate, and a live self-hosted Honcho v3 instance with two-user isolation verified in both directions. A follow-up could adopt an official Honcho SDK adapter, mirroring the OpenViking custom-HTTP → maintained-adapter arc.

### Affected area(s)

Agents / LangGraph (memory backend; opt-in via `memory.manager_class: honcho`, DeerMem remains the default)
