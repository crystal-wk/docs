### Problem summary

TodoMiddleware system prompt is not propagated to model requests

### Affected area(s)

Agents / LangGraph (graph, prompts, langgraph.json)

### What happened?

DeerFlow's custom `TodoMiddleware` registers the `write_todos` tool, but its TODO system prompt is not propagated to the model request.

The custom middleware overrides `wrap_model_call` and `awrap_model_call` without delegating to the upstream `TodoListMiddleware` implementation. Therefore, the upstream logic that injects the TODO system prompt is skipped.

As a result, the model can see the `write_todos` tool, but may not receive the instructions explaining when and how to use it.

## Affected code

- `backend/packages/harness/deerflow/agents/lead_agent/agent.py`
- `backend/packages/harness/deerflow/agents/middlewares/todo_middleware.py`

### Expected behavior

When `TodoMiddleware` is active, its TODO system prompt should be available in the model request's system message.

The behavior should work for both:

- `wrap_model_call`
- `awrap_model_call`

The prompt should also avoid being duplicated if it has already been injected.

### Steps to reproduce

1. Enable plan mode so that `TodoMiddleware` is created.
2. Create a `ModelRequest` with a base system message.
3. Pass the request through `TodoMiddleware.awrap_model_call`.
4. Inspect the system message received by the downstream model handler.

The downstream system message only contains the base lead-agent prompt. It does not contain the TODO system prompt, even though the middleware has a non-empty `system_prompt`.

The `write_todos` tool is registered successfully, but the TODO instructions are missing from the model's system message.
