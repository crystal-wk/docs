### Problem summary

make dev incorrectly reports that pnpm is unavailable even though pnpm is installed and works normally.

### Affected area(s)

Config / setup (make, config.yaml, env)

### What happened?

Running `make dev` from the repository root fails with:

```shell
Checking pnpm...
  FAIL pnpm is unavailable or failed to run
    /usr/bin/python3: can't open file 'scripts/pnpm.py': [Errno 2] No such file or directory
```

However, pnpm is installed:

```shell
node -v
v24.19.0

npm -v
11.17.0

pnpm -v
10.26.2
```

The cause is that `scripts/check.py` constructs `PNPM_SCRIPT_PATH` as a relative path:

```python
PNPM_SCRIPT_PATH = Path(__file__).with_name("pnpm.py")
```

It then launches that path with `cwd=FRONTEND_DIR`. As a result, Python looks for `frontend/scripts/pnpm.py` instead of `<repo>/scripts/pnpm.py`.

`scripts/doctor.py` contains the same relative-path issue.

### Expected behavior

`make check` and `make dev` should locate `scripts/pnpm.py` independently of the caller's current working directory.

### Steps to reproduce

1. Clone the repository.
2. Install Node.js 22+ and pnpm.
3. Confirm that `pnpm -v` works.
4. Run `make dev` from the repository root.
5. Observe that the dependency check reports pnpm as unavailable.

Running the checker from `scripts/` also demonstrates the working-directory dependency:

```shell
cd scripts
python3 check.py
```

This fails because `frontend` is resolved as `scripts/frontend`.

### Relevant logs

## Proposed fix

Resolve the script path before changing the subprocess working directory:

```python
PNPM_SCRIPT_PATH = Path(__file__).resolve().with_name("pnpm.py")
FRONTEND_DIR = PNPM_SCRIPT_PATH.parent.parent / "frontend"
```

Apply the same change to both `scripts/check.py` and `scripts/doctor.py`.
