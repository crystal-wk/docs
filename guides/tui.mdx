The `deerflow` CLI runs the full agent harness embedded in your terminal using the same `config.yaml`, skills, memory, MCP, and sandbox settings as the web UI. No Gateway, frontend, nginx, or Docker services are required — the harness runs in-process, connected directly to the same checkpointer and database your web UI reads.

## Install

The TUI ships as an optional extra to keep the core harness install lean:

```shell
uv pip install 'deerflow-harness[tui]'
```

This adds [Textual](https://textual.textualize.io/) as a dependency. If you prefer pip:

```shell
pip install 'deerflow-harness[tui]'
```

## Launch Modes

Choose the mode that fits your workflow:

| Command | Behavior |
|---|---|
| `deerflow` | Launch TUI when stdin/stdout are TTYs (auto-detect) |
| `deerflow --tui` | Force TUI mode |
| `deerflow chat` | Same TUI conversation surface as `deerflow --tui` |
| `deerflow --cli` | Force headless/classic mode for one invocation |
| `deerflow --tui-transparent` | Use terminal default background instead of DeerFlow palette |
| `deerflow --continue` | Resume the most recent thread |
| `deerflow --resume THREAD` | Resume a specific thread by ID |
| `deerflow --print "question"` | Headless one-shot answer to stdout |
| `deerflow --json "question"` | Headless newline-delimited `StreamEvent`s |
| `deerflow --recursion-limit 250 --print "question"` | Headless one-shot with custom agent-loop limit |
| `echo "question" \| deerflow --print` | Read the question from stdin in headless mode |

<Note>
  Headless runs (`--print`, `--json`) use a recursion limit of `100` by default. Pass `--recursion-limit` when your task requires a longer agent loop. This is a LangGraph super-step budget — it counts both model calls and tool-execution steps, not conversational turns.
</Note>

## The TUI Interface

The TUI is a keyboard-driven chat surface divided into four regions:

**Header** — displays the active model, current thread ID and title, project root, and skill/tool counts.

**Transcript** — shows your prompts, assistant answers, and compact tool-activity cards (for example, `⚙ Read path ✓` with a dimmed result preview). Finalized assistant messages render as Markdown — headings, bold, lists, code blocks, and links. The actively-streaming message stays plain text to avoid reflow jumpiness and snaps to Markdown when complete. Transcript re-renders are coalesced at roughly 16 fps to keep streaming smooth on long threads.

**Status line** — shows the current run state with an animated spinner, model name, thread title, token usage, and an `esc interrupt` hint while a run is active.

**Composer** — a rounded input box at the bottom of the screen. Type `/` to open the slash-command palette.

## Keyboard Shortcuts

| Key | Action |
|---|---|
| `Enter` | Send message or accept palette selection |
| `/` | Open the slash-command palette |
| `Up` / `Down` | Navigate the palette, or scroll input history when the palette is closed |
| `Tab` | Complete the highlighted command (adds a trailing space) |
| `Esc` | Close the palette or overlay |
| `Ctrl+C` | Interrupt the active run, or quit when idle |
| `Ctrl+L` | Redraw the terminal |
| `Ctrl+U` | Clear the composer input |

## Slash Commands

Type `/` in the composer to open the command palette. Available commands:

| Command | Description |
|---|---|
| `/help` | Show available commands |
| `/new` | Start a new thread |
| `/clear` | Remove current transcript rows from display (keeps the thread and persisted conversation) |
| `/goal <condition>` | Set the active thread goal |
| `/goal` | Show the current thread goal |
| `/goal clear` | Clear the active thread goal |
| `/threads` | Open the thread picker modal |
| `/model` | Open the model picker modal |
| `/skills` | List and toggle available skills |
| `/tools` | List configured tools |
| `/mcp` | Show MCP server status |
| `/memory` | Inspect long-term memory |
| `/uploads` | List uploaded files for the current thread |
| `/usage` | Show token usage for the current session |
| `/config` | Show the active configuration |
| `/quit` | Quit the TUI |

Activate a specific skill for a single turn by starting your message with `/<skill-name>`:

```text
/data-analysis analyze uploads/report.csv
```

This loads that skill's `SKILL.md` as hidden context for the current turn, following the same semantics as slash activation in the web UI.

<Note>
  `/clear` removes rows from the current terminal display only. It does not delete the thread or its persisted conversation history. During an active run, `/new` and `/clear` ask you to wait for the run to finish rather than resetting in-flight display state.
</Note>

## Session Goals

Use `/goal` to set a persistent goal for the current thread. DeerFlow surfaces the goal to the agent at the start of each turn, keeping long-running sessions oriented.

```text
/goal Complete a full competitive analysis of the top 5 players in the market
```

Run `/goal` with no arguments to display the current goal, or `/goal clear` to remove it.

## Web UI Visibility

Sessions you open in the TUI appear in the DeerFlow web UI conversation list. The TUI writes conversation metadata to the same database the Gateway reads, owned by the local default user. This means your terminal and web sessions stay in sync — without running the Gateway process.

When the database backend is `memory`, this sync degrades to a silent no-op and the TUI still works; those threads just will not appear in the web sidebar.

## Headless Scripting

Use headless mode to drive DeerFlow from shell scripts, CI pipelines, or other tools:

```shell
# One-shot answer to stdout
echo "Summarize the latest changes" | deerflow --print

# Newline-delimited StreamEvents, piped to jq
deerflow --json "What is the weather?" | jq '.'

# Extend the agent loop for long tasks
deerflow --recursion-limit 250 --print "Analyze this codebase"
```

The `--json` flag emits newline-delimited `StreamEvent` objects, making it easy to consume DeerFlow output from any language that can read stdin.

<Tip>
  Use `DEER_FLOW_TUI=1` as an environment variable to force TUI mode without a flag, or `DEER_FLOW_TUI_TRANSPARENT=1` to persist transparent background rendering across sessions without passing `--tui-transparent` each time.
</Tip>
